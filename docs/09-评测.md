# 09 评测：PPL / 生成 / 对比 / 基准

## 1. 三类评测

```bash
# PPL：语言建模能力（越低越好）
python scripts/10_eval.py ppl --model-path checkpoints/pretrain/latest.pt \
  --ppl-file data/pretrain_eval.jsonl

# 生成样例：直观感受（--chat 走对话模板）
python scripts/10_eval.py samples --model-path checkpoints/sft/latest.pt --chat

# RL 对比：RM 打分 + 胜率（SFT vs RL）
python scripts/10_eval.py compare \
  --sft-path checkpoints/sft/latest.pt \
  --rl-path checkpoints/dpo/latest.pt \
  --rm-path checkpoints/rm/latest.pt
```

## 2. 指标解读

- **PPL**：`exp(平均 NLL/token)`。64M 小模型在 mini 语料上 20~50 正常；
  跨 tokenizer 比较时用 BPB 更公平（词表大小影响 PPL 基数）；
- **生成样例**：看语法通顺、指令遵循、长度控制，小模型「胡编」是常态；
- **胜率/平均 RM 奖励**：RL 阶段的核心信号，但 RM 本身有偏，需人工抽检。

## 3. 第三方基准（可选）

导出 HF 格式后可用 lm-evaluation-harness 跑 C-Eval 等：

```bash
python scripts/10_eval.py lm-eval --export-dir checkpoints/hf --tasks ceval-valid --limit 100
```

小模型分数通常很低，教学价值在于**跑通流程**与观察相对提升（SFT vs RL）。

## 4. 评测数据从哪来

- 预训练留出 1k 行文本做 `pretrain_eval.jsonl`（`02_prepare_data.py` 下载时按比例留出）；
- 偏好评测复用 `dpo.jsonl` 前 N 条；
- 生成样例可用 `--prompt-file` 提供自定义列表。
